# RelayNest 分阶段开发计划

> 需求依据：`PRD.md` 与 `ARCHITECTURE.md` §1 用户已确认的 C-01～C-05。  
> 执行约定：阅读根 `AGENTS.md`、`docs/CONTRIBUTING.md` 和关联设计；遵循中文重要代码注释、受影响模块检查、每个独立任务本地 Conventional Commit、不自动推送。

## 1. 发布分界和执行规则

**核心版发布**覆盖 Bot Hub、Web 管理、Android Bot 功能/后台补偿/多设备、MoviePilot 集成、fnOS 部署和构建发布。**RelayShelf v0.4.4 接入排在核心版发布后，优先级最低，不阻塞核心版。** 原 PRD 的首版完整覆盖与双端统一登录要求，按用户 2026-10-21 确认延期；不能据此取消后续完整覆盖目标，也不能把延期验收计为已通过。

当前已有：PRD 审查、用户澄清、固定版本部分源码研究、三个技术文档。当前没有：业务工程、正式 OpenAPI/DDL、运行 PoC、目标真机/服务环境、签名配置和发布验证。源码分析与 PoC 通过必须分开记录。

每个编号任务控制为一个可审查的工作单元；同一阶段内也应按依赖分别实现和提交。每轮完成说明修改、验证、提交 SHA 和遗留风险。测试优先覆盖有真实失败风险的边界，不为每个 DTO 或简单包装函数机械增加测试。阶段交付记录写入已有相关文档或提交说明，不自动扩张为大量新文档。

```text
P0 环境/版本/契约准备
 ├─ P1 MoviePilot 最小兼容 PoC ───────────────────→ P10 正式插件
 ├─ P2 FCM 真机 PoC ───────────────────────────→ P9 通知
 └─ P3 工程/契约 → P4 身份/Bot → P5 消息/附件 → P6 可靠队列/清理
                                      ├─ P7 Web 管理
                                      └─ P8 Android 同步/对话 → P9 通知
P7 + P8 + P9 + P10 → P11 整体联调
P3 起建立 CI，P11 → P12 发布部署验收 → 核心版
核心版 → P13 RelayShelf 完整矩阵/PoC → P14 原生接入 → P15 扩展版验收
```

上述分支表示依赖关系，默认由当前任务顺序执行；不是授权启动子代理或新聊天。P1 受阻时允许推进通用 Hub 模块，但不能在未经用户确认的情况下豁免 AC-07 或宣称核心版全部完成。

## 2. 阶段任务

### P0：环境、版本与审查基线

**目标**：在不开发业务功能的前提下，补齐可复现验证条件。

**任务**：

- P0.1 核对三个文档和 C-01～C-05；确认源码 ref 可解析，记录实际测试镜像 digest 和配套 MP 前端版本。
- P0.2 收集目标手机/平板、Android/ColorOS、Google 服务、NAS CPU 架构/本地卷、OpenWrt Nginx/公网 Origin（含端口）。确认 Android minSdk 范围，影响用户设备可用性时先确认。
- P0.3 检查真实 Git checkout、远程及忽略规则；当前目录 `git status` 返回非仓库，须恢复/获取真实 checkout 后才满足本地提交要求。不得伪造提交 SHA。

**依赖**：现有 PRD 和用户澄清；外部测试环境由拥有者提供，不自动操作现网。

**交付物**：锁定测试版本/环境信息、未具备条件列表、文档范围复核结果。

**测试**：源码 tag/commit 一致性检查；明确 Secret 存放位置但不打印值；检查 Nginx 外部 Origin 与内网拓扑；Git 状态真实可读。

**完成标准**：后续 PoC 有可运行且可复现的测试对象；缺少真机/Google 凭据时明确阻塞 P2，不能把模拟器测试替代 ColorOS 真机。

### P1：MoviePilot v3.1.5 最小兼容 PoC（高风险门槛）

**目标**：验证专用插件是否能完成完整双向链路，先于正式插件开发。

**任务**：

- P1.1 继续追踪通知配置 UI/后端、服务发现、模块契约、固定渠道枚举和能力判断，列出每条调用链；当前源码确认入口见技术设计 §10。
- P1.2 在独立测试实例制作最小可移除插件及本地协议桩，不接现网业务操作；验证自定义配置保存、启动恢复和目标插件选择。
- P1.3 验证广播/管理员与用户定向、文本入站、业务回复、媒体/种子候选、callback、引用、直接发送 ID、编辑、附件。
- P1.4 验证事件监听和 provider 不重复发送，既有渠道不受影响；插件停止/重载无残留轮询线程；形成通过/失败证据和可行路径。

**依赖**：P0；测试实例；只需最小 Hub 协议桩，不依赖正式 Hub 完成。

**交付物**：最小 PoC、固定源码路径、脱敏请求/响应、逐项结果和候选设计；不冒充正式插件。

**测试**：自定义配置 → 主动通知 → 文本入站 → 正确会话回复 → 按钮回调全链路；另含搜索列表和编辑、两个 Bot 上下文、其他渠道非回归。

**完成标准**：原定纯插件边界下完整链路实际通过；若需要借用其他渠道、枚举/能力猴子补丁或核心修改，标记未通过，提交最小改动/替代方案/范围影响并等待用户选择，暂停 P10 定稿。仅发现 `get_module()` 或成功发一条通知不能完成此阶段。

### P2：Android FCM 真机 PoC

**目标**：识别目标环境后台行为，验证通知方案的实际限制。

**任务**：

- P2.1 锁定 Android/Firebase SDK 兼容版本，在目标设备登记注册，验证 Hub 所在网络可访问 FCM。
- P2.2 最小 data 提示、WorkManager 调度及前台补偿验证；测试注册更新、失效和退出清理。
- P2.3 按场景记录发送、设备收到、任务运行和再次打开同步的时间，区分离线、强制停止、系统杀进程、锁屏和通知关闭。

**依赖**：P0；Firebase 项目、测试凭据和目标设备。没有条件时保留未执行，不伪造时间记录。

**交付物**：可移除最小测试客户端/发送桩、设备和网络矩阵、实测结果及限制；不得包含服务账号秘密。

**测试**：前后台、锁屏/Doze、Wi-Fi/蜂窝切换、无 Google 服务或网络不可达、通知拒绝、重启、Token 变化、强制停止后手动重开；ColorOS 额外覆盖系统后台限制设置。

**完成标准**：明确每种场景结果，验证推送失败仍可在重新连接后补偿。无需所有场景实时到达；若实际体验要求改变 FCM/无常驻服务边界，先报告用户，不自动换架构。未测试 ColorOS 不宣称已兼容 ColorOS。

### P3：Monorepo、契约和最小 CI

**目标**：建立可以独立构建、校验和提交的工程基础。

**任务**：

- P3.1 建立 android/server/web/integrations/moviepilot/deploy 的必要工程，锁 Go、Kotlin、Gradle、JDK、Node、包管理器及依赖；不初始化 RelayShelf 源码或数据库。
- P3.2 根据详细设计生成正式 OpenAPI（拟放 `server/api/openapi.yaml`）和第一批迁移；完善消息/callback/同步/错误 Schema、示例及兼容规则。
- P3.3 建立按路径触发 Go 检查、Web 类型/构建、Android 编译、插件静态检查；仅构建健康服务和空管理入口，不趁机实现业务。

**依赖**：P0、已有核心技术设计；P1/P2 的具体适配未完成时保持模块接口边界。

**交付物**：可构建 Monorepo、依赖锁文件、正式 API/DDL 初稿、最小 CI。

**测试**：干净环境按锁文件构建；Schema 校验和示例校验；静态 Web 可嵌入 Go；生成物可复现且没有凭据。

**完成标准**：各模块最小构建通过，CI 不要求 RelayShelf 在线。影响产品/权限的契约新增先确认；普通字段命名由实现者决定。

### P4：管理员、设备和 Bot 生命周期

**目标**：先建立后续所有访问的权限与撤销基础。

**任务**：

- P4.1 SQLite 初始化/迁移与管理员 init/reset-password，安全摘要、限流和会话过期。
- P4.2 Web Cookie/CSRF 和 Android 设备 Bearer；会话查看/远程撤销，可信代理校验。
- P4.3 Bot CRUD、启停、两套独立凭据及 send/receive，重置代次和二次删除确认。

**依赖**：P3。

**交付物**：可通过 CLI 初始化的 Hub、身份/Bot API、权限回归测试。

**测试**：首次初始化竞争、重复 init 拒绝、密码不进入参数日志、重置撤销旧会话；Bot A 不能访问 B；Webhook 不能进入 API/管理路由；receive-only 不能发送；旧 Token 在等待中及提交时失效；伪造转发头不能改变 Origin；远程撤销不影响其他设备。

**完成标准**：上述权限矩阵通过，重启会话/凭据状态正确；未建立唯一管理员时不开放无保护管理入口。

### P5：消息、编辑、附件与标准 Webhook

**目标**：实现持久化成功才回执的基础消息闭环。

**任务**：

- P5.1 消息 ID/排序/版本、幂等创建、回复引用、Markdown/按钮验证、正文分页和共享已读。
- P5.2 应用消息 CAS 编辑、Android 只同步展示、消息变更事件；callback 独立持久记录与参数快照。
- P5.3 附件 staging/ready/deleting 状态、流式上传、下载权限、Range 和恢复扫描。
- P5.4 标准 Webhook 创建路径；错误格式、请求限制和敏感日志剔除。

**依赖**：P4；投递表随消息事务写入，完整调度在 P6。

**交付物**：完整基础消息 API、附件恢复实现、标准 JSON 接入示例。

**测试**：提交失败无成功回执；提交后回复丢失再试不重复；同键不同内容冲突；跨 Bot 引用/附件拒绝；编辑并发冲突和按钮过时；文件 flush/rename/DB 更新故障；缺失文件与路径穿越；超限 413；URL 不触发抓取；Webhook 密钥不获得编辑/下载权限。

**完成标准**：消息与附件关联一致，未完成文件不被消息引用；幂等/编辑/权限的 API 契约测试通过。

### P6：可靠投递、失败队列和清理

**目标**：把至少一次投递与到期清理做成可恢复状态机。

**任务**：

- P6.1 claim/lease/ACK/renew、退避与次数、重启扫描；不在等待中占数据库事务。
- P6.2 失败元数据列表/手动重试代次；应用事件 ID 稳定，区分重投与业务重跑。
- P6.3 历史和附件保护条件、普通消息到期、删除事件/floor、幂等墓碑回收。
- P6.4 Bot 停用/恢复/API 凭据重置时释放租约，永久删除取消保护，基础资源与健康状态。

**依赖**：P5。

**交付物**：投递状态机、清理任务、可靠性/故障注入测试和管理投影。

**测试**：并发消费者不领取同一有效租约；claim 回复丢失重投；ACK 丢回执/重复 ACK；旧租约 ACK 拒绝；停用不自动耗尽次数；重置旧 Token 不能 ACK；重启续投；失败手动重试仍用原事件 ID；30 天清理不删未 ACK/failed 文件；离线设备不阻塞；父消息/附件保护竞态；清理与下载/编辑并发；磁盘满明确失败。

**完成标准**：所有状态转移和恢复路径有可重复证据，保护不依赖内存；失败列表不泄露正文/原始异常；无需任何外部队列服务。

### P7：Web 管理后台

**目标**：提供日常管理和故障投递操作，不建设聊天客户端。

**任务**：

- P7.1 登录、Bot CRUD/启停/删除、两类凭据一次展示和单独重置。
- P7.2 系统配置、会话撤销、连接/健康/失败计数与投递元数据重试。
- P7.3 静态产物嵌入 Go，基础可用性/加载/冲突错误提示。

**依赖**：P4～P6。

**交付物**：内嵌 Web 管理页面与管理操作自动化验证。

**测试**：Cookie/CSRF/同源、凭据只显示一次、删除确认、缩短保留期限提示、会话失效、并发版本冲突、手动重试幂等；检查 DOM 与管理响应均不包含正文、callback_data、附件下载链接或历史分页。

**完成标准**：AC-01 的 Web 部分与失败管理通过，无聊天和消息历史入口。

### P8：Android 登录、缓存、Bot 对话及同步

**目标**：先交付不依赖后台推送的原生核心客户端。

**任务**：

- P8.1 Hub 地址/登录、设备会话加密保存、过期/撤销、本地状态按服务实例隔离；核心版不强制配置 RelayShelf。
- P8.2 Room、SyncCoordinator、WS 提示和增量/重建；本地 outbox、附件发送与未知结果恢复。
- P8.3 Bot 列表、未读、详情/分页、Markdown/图片/文件、回复/按钮、编辑展示、准确状态文案。
- P8.4 Bot 管理、全局配置、设备会话和失败队列管理，实现与 Web 相同生命周期能力。

**依赖**：P5/P6 的正式契约，P0 的设备兼容范围。

**交付物**：可安装调试 APK、原生对话闭环和多设备同步。

**测试**：两设备交错读/写、水位不倒退；杀进程发生在 Room 批次中间；WS 连接窗口变更；低 revision 不覆盖高 revision；游标过期重建且未发送 outbox 不丢；重建期间 Bot/消息删除和编辑；自定义 HTTPS 端口；断网发送重复重试；会话撤销后不继续自动发消息；单向 Bot 无发送能力。

**完成标准**：前台双向闭环、共享已读和设备独立状态通过；消息状态不把 ACK 写成业务成功；Android 无已发送消息编辑入口。

### P9：Android FCM、WorkManager 与通知偏好

**目标**：将已完成的前台同步接入可降级后台提醒。

**任务**：

- P9.1 Hub 推送待办/合并/重试、设备注册更新/撤销，Android data 提示接入统一同步。
- P9.2 网络约束周期 WorkManager、前台立即补偿、进程重启恢复；前后台 WS 生命周期。
- P9.3 全局/Bot 开关、静音跨午夜及时区、锁屏预览、系统权限、按消息 ID 去重与共享已读取消。

**依赖**：P2 的环境结果、P8。

**交付物**：带后台通知的 APK、脱敏推送配置说明、目标设备验证记录。

**测试**：P2 场景在完整 App 中回归；FCM 不含正文和秘密；关闭通知仍同步；编辑不重复响铃；跨设备已读取消；重建不轰炸历史提醒；通知发布/本地状态之间崩溃；注册刷新、旧注册失效、退出后的延迟推送；Google 网络失败不使 Hub 接收失败。

**完成标准**：补偿正确、降级可解释、不承诺锁屏准时；所有声明支持的设备都有实测信息。不得以常驻前台服务补救未确认的行为。

### P10：MoviePilot 正式插件

**目标**：在 P1 验证通过的扩展路径上实现可靠专用适配。

**任务**：

- P10.1 插件配置、Bot/MP 用户/source 绑定、启动/停止/重载和错误状态。
- P10.2 持久 Inbox 和必要附件字节后 ACK、Outbox 发送幂等、结果/引用/附件/编辑 ID 映射。
- P10.3 分别覆盖通知、定向回复、候选列表、callback 和直接发送，沿用 MP 业务权限与确认。
- P10.4 插件包/安装说明和固定 v3.1.5 的兼容测试；不复制 MP 核心进本项目。

**依赖**：P1 完整通过或用户另行批准的替代设计；P6/P8。未通过 P1 不能把本阶段标为可直接编码。

**交付物**：可安装专用插件、固定版本兼容证据、部署和升级说明。

**测试**：两 Bot、两设备正确会话；普通/异步/候选路径不漏不重；断网和 Hub 重启、MP 重启、ACK 回执丢失、编辑/附件失败；非管理员业务输入由 MP 拒绝；不影响原有渠道；回调重投不绕过业务确认。

**完成标准**：AC-07 完整端到端通过，明确仍存在的业务幂等窗口；未经批准不改 MP 核心、不宣称插件绕过固定枚举问题。

### P11：整体联调与可靠性验收

**目标**：验证真实组件组合，发现单模块测试覆盖不到的状态交叉。

**任务**：

- P11.1 fnOS 测试环境接入 OpenWrt HTTPS/WS/Long Polling/附件代理；两台 Android + MP。
- P11.2 正常消息、回复、callback、编辑、附件和失败重试全流程；凭据重置、Bot 停用/恢复/删除交叉测试。
- P11.3 30 天时钟模拟和现存数据兼容、长离线重建、资源压力/磁盘满/强制退出恢复；核对日志与公开健康接口信息范围。

**依赖**：P7～P10；P1 和 P2 的结果不能用源码审查代替。

**交付物**：按 AC 编号的脱敏联调记录、问题清单和修复提交。

**测试**：在每个持久化边界注入退出；对照稳定 event_id 与消息数核对丢失/重复；附件回收与下载竞态；慢 WS 客户端不耗尽服务；清理不阻塞交互；恢复后不伪造完整历史。

**完成标准**：核心验收矩阵全通过或由用户明确批准偏差；数据丢失、越权、未确认的 MP 核心改动均为发布阻塞。

### P12：CI/CD、fnOS 部署与核心版发布

**目标**：形成可正常安装、更新和重复构建的正式交付。

**任务**：
