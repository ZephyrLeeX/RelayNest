# 任务执行与交接规则

## 权威与授权

- 产品、架构和技术约束分别以 [PRD](../PRD.md)、[架构](../ARCHITECTURE.md)、[技术设计](../TECHNICAL_DESIGN.md) 为准；工程与提交遵循 [CONTRIBUTING](../CONTRIBUTING.md)。本次任务目录重组不改变产品需求或验收标准。
- 迁移后，七个模块文档中的未完成任务条目是唯一执行状态来源；完成后将条目及证据移入 [COMPLETED](COMPLETED.md)，模块只保留必要引用，不复制状态。[PROGRESS](../PROGRESS.md) 仅作模块摘要。旧 registry、cards、reports 及两份协议已由本结构替代，历史只从 Git 查阅。
- 总调度是任务状态唯一维护者；worker、审计和集成角色只回报精简证据，由总调度写回相应任务条目。不得再建一份 registry、每卡报告副本或另一套状态表。
- 用户已授权持续推进 P3～P15 范围，普通实现、修复和本地检查不逐任务确认。核心版优先；RelayShelf 仍须满足实质 G-SHELF：核心版实际完成／发布证据，以及已有用户启动后续范围授权；准备报告不能代替实际条件。
- 需求、架构、安全、外部接口或开发范围的重要变更，汇总证据、选项与建议后请用户决定。RelayShelf 后端／数据库、MP 核心及既定后台架构不得擅改；Bot Hub 仅传输、存储和路由消息。
- 现场部署、MP 重建、破坏数据操作、远端推送和 Release，应先备齐可审阅的具体结果，再由用户最后确认；同一行动已有明确授权时不重复询问。暂停要求立即停止新派发并收集在途交接。不自行建立新聊天、定时任务或对外消息。

## 角色与闭环

- 总调度只读任务元数据、依赖、摘要与用户答复，维护状态、文件占用和授权；不研究源码／外部技术资料、不实现、不跑测试、不代审，也不执行 Git 提交、切分支或集成。技术细化、工作树准备与状态快照提交交相应角色。
- 规划角色处理有限目标、上下文估算、拆分及依赖／接口影响；实现或研究角色完成单任务、相关验证与本地提交；审计角色独立检查固定 SHA，不边审边修；修复角色只处理编号问题；集成角色验证准确提交组合与目标分支。
- 每次只派一个有限任务。流程为：实现／研究 → 单独本地 commit → 不同 agent 固定 SHA 审计 → 编号修复与新 SHA 重审 → 准确集成组合及相关检查 → 总调度记录完成。研究、验证任务也审查证据真实性及范围。
- 审计结论为 PASS、CHANGES_REQUIRED 或 BLOCKED；发现须有稳定编号、位置／证据、触发条件、影响、修复方向和复验方式。独立审计自行读取有关差异及代码，不仅复述开发报告；重点检查权限、事务、并发、恢复、范围和敏感数据。
- 审计通过不豁免必跑检查。修复后按新 SHA 复审并核对旧问题；多轮无法收敛时重新规划或提交用户决定。审计／集成步骤关联被审任务，不把父任务 done 设为前置而造成死锁。
- 集成记录目标分支、实现 SHA、审计证据、集成前后 SHA、实际检查及冲突。精确提交已在目标分支时只核实范围，不重复 cherry-pick；冲突产生新业务代码或契约变化须重审，无冲突组合也执行受影响检查。
- 阶段和跨组件验收须独立验证实际组合，依赖完成不等于验收自动通过。WIP、PoC、桩、准备材料、局部检查、NOT_RUN 均不得冒充正式验收；用户批准的限定例外保留原范围。负面研究可以完成，相关兼容门槛仍可能受阻。

## 单任务输入与预算

派发前核对以下信息，缺基线、依赖未集成、范围含糊或超预算时先澄清／拆分，不自行扩展：

- 任务 ID、角色、单一目标与验收；原阶段／旧 ID 映射及禁止事项。
- 真实基线 SHA、工作目录／分支、精确允许路径与职责、相关文档章节。
- 已集成依赖及 SHA 摘要、冻结接口、公共文件／迁移编号占用。
- 当前环境及版本、必跑检查、外部条件和已知限制；未知外部接口先查证。

新 worker 使用全新上下文，不继承整个总聊天；默认初始输入 ≤12k tokens，通常仅 3～5 个主要实现文件及必要测试。输入、预计工作材料、工具输出与结果合计不超过模型窗口 60%，至少留 25% 交接余量；实际窗口较小时取更小限制，不伪造精确 token 统计。

超出职责／主要文件预算或出现上下文风险，停止扩展并提交 checkpoint：已完成部分、准确 SHA／未提交路径、未跑检查、风险和精确下一步。规划角色按接口先行、实现、组合验收拆分；子任务保留完整目标／范围／验收／依赖，父任务待全部子项及收口验收后完成，不能丢验收或引入依赖环。

## 并发、Git 与恢复

- 每个 worktree／Git index 同时只有一个写入者；开发释放后才对固定对象审计。授权并行时使用隔离 worktree，固定基线、分支、owner 与释放条件；公共 API、迁移编号和共享构建配置串行协调，契约先集成再派依赖实现。
- 实现前核对实际目录与已有实现，任务中的规划路径不是源码存在的证明；命名不同先给等价映射，不为匹配旧卡搬目录。
- 每独立任务单独本地 Conventional Commit；提交前检查 diff／status 并执行相关检查，只 stage 明确路径，不用 `git add .`。不覆盖或提交用户／其他任务未提交内容，不入库密钥、正文／原始敏感日志、构建产物及临时文件，不擅自 reset、clean、force 或改写历史。
- worker 失联、创建工具结果未知或恢复聊天时，先核实 agent、实际工作树、未提交内容及提交，避免重复派发和丢工作。总调度只恢复有关元数据和未闭环摘要，不重读全部历史或凭聊天记录标完成。
- 依赖修复或契约变化，由规划／审计角色报告影响范围和重开建议，总调度登记；不能根据过时审计继续放行。

## 状态、证据与调度

```text
todo → ready → running → review → integrating → done
                        ↑   ↓
                        changes_requested
进行中 → blocked / needs_user → 条件解除后回原未完成步骤
deferred → 已授权且实质门槛满足后 → todo
```

- `ready` 必须授权、依赖已集成、门槛满足且工作区可用；`review` 表示实现已提交待独立审计；`integrating` 必须最终审计 PASS；`done` 必须验收、最终实现审计、精确集成及证据齐全，随后迁入 COMPLETED。
- `blocked` 写明环境／依赖／工具／必需检查缺什么；`needs_user` 写清需决定的问题和最小输入。只暂停相关分支，继续独立任务；缺手机、NAS 或签名不能被其他检查替代，也不阻塞无关本地工作。用户已安排最终真机验收的项目按该决定执行，不反复索取环境。
- MP 完整双向、FCM 真机、RelayShelf API 矩阵／原生 PoC 等门槛，以相关任务与 PRD 的实际验收为准。触发既定停止规则就停止该分支，不绕过或自行豁免。
- 每次派发前在任务条目记录 owner、角色、基线、状态、路径／锁及依赖；创建成功后补 agent/session ID。每次转换记日期、原因与前状态，保留必要短历史；审计／修复／集成可在同一条目用 A01／F01／I01 等编号记录，不另铺大量报告。
- 交接仅含：任务／角色／结论；真实基线、实现及提交范围；变更路径；实际检查命令、环境、pass／fail／not_run 与原因；验收证据、接口交接、限制和待决定事项。实现提交后再记录其 SHA，不在提交中预写自身 SHA。无证据不得填通过。
- 审计补充精确被审 SHA、发现编号和限制；集成补充前后 SHA 与组合检查。总调度将摘要写入任务证据段；必要的长技术报告才按需保存并链接，不默认为每卡生成实现／审计／集成固定文件。纯证据元数据变更不机械重跑全业务矩阵。
- 每轮简报真实完成、进行中、受阻原因及下一步；完成授权范围后停止，不因任务完成自动部署、推送或发布。

## 启动用法

读取 AGENTS.md、本规则、对应模块的未完成条目和必要的 COMPLETED 依赖证据，核实当前真实工作区／在途任务与用户授权；按上述单任务输入派发有限 worker，依据独立审计和准确集成证据推进。无子 agent 工具时报告缺少执行能力，不用创建普通聊天冒充。其余产品背景按需从设计文档读取。
