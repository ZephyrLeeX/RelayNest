# Agent 开发任务目录

本目录将 [DEVELOPMENT_PLAN.md](../DEVELOPMENT_PLAN.md) 拆成 **140张初始任务卡**，覆盖 P0～P15，并按执行需要增加有限子卡。当前已获用户授权持续推进 P3～P15；实际状态以台账、独立审计和集成证据为准，不以任务卡存在代表完成。真实部署、远端推送和公开发布仍需最后确认。

## 使用入口

- [当前项目进度：已完成／开发中／未开始](../PROGRESS.md)：按功能列出的进度快照与外部条件。

- [总调度规则与启动提示词](ORCHESTRATOR.md)：总 agent 只读任务元数据/摘要，派发开发、独立审计、修复及集成，不写业务代码或代做审计。
- [子 agent 执行、审计和交接协议](WORKER_PROTOCOL.md)：上下文预算、范围、提交、审计/修复和集成模板。
- [机器可读台账](registry.json)：依赖、发布线、唯一任务状态和门槛。总调度维护执行状态；历史规划初始状态不代表当前进度。
- [执行报告目录](reports/README.md)：报告命名要求及实际执行证据；具体任务报告以台账引用为准。

**核心版优先**，P13～P15 RelayShelf 已在后续授权范围内，但核心版实际完成及 G-SHELF 门槛尚未满足，仍保持后置。MP 完整双向验证未通过不得豁免AC-07；FCM真机缺失不得伪造通过。

## 颗粒度与预算

一张卡只含一个可独立验证的交付目标。预算是派发约束，不是固定模型上下文容量承诺：默认输入最多12k tokens，常规代码变更3～5个主要文件；新 worker 使用全新上下文，只加载相关章节、依赖摘要和局部代码。复杂协议/跨模块/全量矩阵验收必须在预算不足时继续拆分，不能把一整阶段塞给一个 agent。

每个开发任务都有独立审计和集成步骤，其ID按统一协议动态产生，避免为每张卡复制两份相同的审计文字。修复、补充任务登记到同一台账后才执行；不知道的现有功能不提前编造分支任务。

## 依赖与风险门槛

依赖只有在 `done` 且已集成时满足。外部条件只阻塞相关分支：缺手机不妨碍服务端契约，缺NAS不妨碍本地单元测试；但实际验收不得跳过。阶段依赖由任务卡细化，例如只读源码研究不需先实现Hub。

| 门槛 | 证据来源 | 后续约束 |
| --- | --- | --- |
| G-GIT | P00-02 + 可用已提交基线 | 开发/审计固定SHA及安全集成必需；不擅自纳入已有未跟踪文件 |
| G-API | P03-04～07 + 独立审计/集成 | 服务端与客户端依同一已冻结契约，未完成片段不伪装完整 |
| G-MP | P01-06 + 全链路证据及审计 | 正式MP插件；若需改核心/借用渠道先询问用户 |
| G-FCM | P02-04 + 目标真机证据及审计 | 真实FCM适配与正式通知验收，不要求所有场景实时 |
| G-CORE | P11-05 + 核心AC证据及审计 | 核心版候选资格，AC10双端/AC11保持延期 |
| G-DEPLOY | P12-05 + 真实安装升级证据及审计 | 核心版发布准备；真实发布另需授权 |
| G-SHELF | 核心版实际完成/发布证据 + 用户启动后续范围授权 | 启用P13～15；P12-06仅准备完成不能自动开启 |
| G-SHELF-API | P13-04 + 完整矩阵/原生PoC审计 | P14功能开发，缺口不擅自改后端 |

门槛初始均 pending；当前结果见台账，不能根据有任务卡就标 pass。总调度只核对审计结论和证据链接后记录门槛；技术判定交验证/审计agent，不由总调度研究源码替代。
