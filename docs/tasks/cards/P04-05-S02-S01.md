## 实现与真实 SQLite 验收

父 S02 的全部工作和验收逐项保留，以下是本次收敛的完整证据清单，不得只补 happy path：

1. 安装元数据持久化：同安装 S1/S2、另一安装 B 同时存在，各 Session 新 UUID/凭据；关闭重开仍保留，撤 S1 不影响 S2/B；重装新安装 ID 与 Web 原有登录行为保持。不新增安装登记/重命名/批量接口。
2. 有界列表：完整公开元数据、确定排序、不透明 cursor、默认/最大/负数/非法 cursor 与尾页边界；无跨页快照承诺。按真实数据库 generation、revoked、idle/absolute 过滤，时间 UTC，无 token/hash/CSRF/provider token。字段和错误对照冻结 API，现稿分页参数仅候选实现。
3. 精确撤销：仅按不可复用 Session.id，传 device_id 不回退；目标未知/已失效统一未找到；同安装、他安装、Bot 凭据隔离。旧 token 的 Inspect/Authenticate/真实 RequestSecurity 后续鉴权失败；重登新 Session 后旧 ID 重试或迟到请求不影响新 Session。
4. existing Tx：通过真实 RequestSecurity 产生 actor，验证私有 store/issuer/issued 绑定，伪造/篡改/跨 SessionStore actor 拒绝且无副作用；只在同一 `Store.Write` 中复核 actor 当前代次、撤销及期限，业务写与 changes、成功续期共同提交。复核失败、业务/changes 错误和事务失败必须全部回滚，失败不续期；成功续期不得越过 absolute。测试实际持久结果，不用 mock Tx 代替。
5. 提交前失效及竞争：actor 在入口后/提交前发生代次重置、撤销或到期不能撤目标；目标撤销/到期竞争、重置竞争及自撤边界，必须验证不会误撤别的 Session。使用确定性屏障或受控时钟，报告并发串行化和自撤末尾复核的真实证据；不能用 sleep 或仅运行 race 代替断言。
6. hook：目标撤销和当前 token logout 共用精确 ID 通路；假订阅器核对真实提交后已可见、每次成功一次、错误/回滚无通知、不早发。并发替换/调用 hook 无 race。无真实 WS/provider 运行时，E2E 明记 `NOT_RUN`，不得声称关闭连接或原子解绑映射；P09 实际持久化失效和发送/回调前复核义务保留。

裸 `*sql.Tx` 没有公开所属 DB 查询；原实现的可信同库接线约定已由 [A01/F01](../reports/P04-05-S02-S01-A01.md#编号发现) 判定未满足同 Store 边界，P1 阻断。按 [F01 修复卡](P04-05-S02-S01-F01.md) 改为 SessionStore 自持正确 Store.Write 的受控业务闭包，删除或私有化公开裸 Tx 鉴权/续期入口；不得以披露限制替代修复，也不要求弱化安全边界。上述第4项 existing Tx 验收改由受控入口承载同一业务/changes/成功续期事务，actor binding、代次与错误全回滚全部保留；六矩阵及自撤尾部检查不减少。修复后由不同 agent 固定最终组合 SHA 重审并精确集成，才允许收口及下游消费。
