## 工作与验收

1. 沿现有 `sessions.device_id/device_name/client_type` 持久化安装标识与会话元数据关联；Android 同安装可多 Session，各自新 UUID/凭据，重装由新安装 ID 区分；Web 仍沿现有登录生成设备 ID。内部关联/索引不引入新的设备登记、重命名或安装批量操作 API，不强制新增安装表或改变 Session 字段含义。
2. 实现当前管理员有效 Session 有界分页：完整 `DeviceSessionPage`、稳定确定排序和不透明 cursor、合法 limit 边界；服务端 UTC 到期时间，无跨页快照承诺。按数据库真实 generation、revoked、空闲/绝对期限过滤；返回元数据结构，不携带 Token、hash、CSRF、provider token。字段/错误沿冻结契约。
3. 新增按 `Session.id` 的撤销能力，保留现有按当前 token 的 `Revoke` 用途。真实写事务提交前复核 actor、目标归属/有效性，目标未知/已失效统一未找到；不得先读目标再无条件写。A、同安装 S2、他安装 B、Bot 凭据严格隔离；传入 device_id 不回退选择会话；撤 S1 后重新登录或迟到重试不得影响 S2。
4. 提供按不可复用 Session.id 通知的提交后连接失效钩子；目标撤销和当前 logout 使用同一失效通路，不在失败/回滚前发成功通知。现无 WS/provider 运行时，钩子测试仅验证调用时序、身份和无副作用，不宣称真实关闭连接或原子解绑厂商映射。P09 后续必须将实际映射失效与会话撤销事务整合、发送/回调提交前复核 Session 身份和有效性，不能以本钩子代替持久化安全。
