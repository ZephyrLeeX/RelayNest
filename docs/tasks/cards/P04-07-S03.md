# P04-07-S03 Bot 生命周期真实 HTTP 适配补充卡

## 前置与目标

- 补充卡，不扩大 P04-07 原存储父卡的完成含义。依赖：P04-07、P06-07、P04-07-PLAN01，以及设备 HTTP 装配任务 P04-05-S03 的最终独审/集成（调度已核定真实 ID）。本恢复基线未含动态新增卡，派发包须取调度权威 registry 与该卡最终精确 SHA。
- 完整职责：接入已冻结的两个凭据 reset 与 DELETE HTTP，并验证现有 PATCH 启停经过完整生命周期事务。P06-07 必须已经完成 API reset 的取消旧轮询/撤销租约/重排和永久删除级联，不能先发布基础成功响应。
- 最小上下文：OpenAPI 三个 operation/请求响应、安全错误通则，T4.3、P04-06-S02-I01、S01/S02/P06-07/设备装配最终交接；局部 bots handler、router、main 安全装配和对应测试。

## 范围与实现约束

- 建议允许 `server/internal/httpapi/bots.go`、`server/internal/httpapi/router.go`、`server/cmd/relaynest/main.go` 及对应测试（3–5主要实现文件以内）。只读 API、SQL、auth/storage 和 bots 契约；发现业务仓储不足交回，不扩大本卡修复。
- 复用 `publicRequestSecurity` 与 BotAuthorize/SessionStore.WithAuthorizedWrite；认证、目标检查、业务+changes+renew 仍为同一受控事务，Cookie 写维持既有 CSRF/同源规则。Bot 凭据不授予管理权限；跨 Bot、撤销会话与事务内失效必须拒绝。
- reset API 无冻结的 expected_version 请求体，不擅加必填字段。返回既有 IssuedAPIToken/IssuedWebhookKey，no-store，普通查询不泄密；DELETE 仅接受冻结的 confirm_name/expected_version，成功204，取消确认不请求服务端。
- 当前 OpenAPI reset 仅列200/401/403/404/429/503，未冻结内部耗尽等错误的对外映射；派发前调度确认沿现有通则可复用的响应，若必须新增状态/code/请求结构，先具体提案经用户确认并在契约任务串行集成，本卡不擅改 API。
- G1 三项方向已获批准，但 C01 实际契约尚未重新冻结：本卡不猜未来签名/header。若实施时 G1 已集成，以真实集成 SHA/契约重核；不能覆盖设备或身份任务未提交装配。

## 验收与检查

- [ ] 通过真实路由覆盖 Android Bearer、Cookie+CSRF/同源、Bot凭据拒绝、缺失/撤销会话、跨Bot、事务中失效；失败不续期/不写业务或changes。
- [ ] 两 reset 响应仅对应新秘密；旧代次在 inflight 最终 Tx 拒绝、API reset 撤销租约/重排，Webhook reset 不影响 API 租约；消息/失败记录保留。
- [ ] DELETE 错名/旧版本/取消无副作用，正确确认完整级联并保留 tombstone；受保护队列取消、共享附件引用不误删证据必须来自 P06-07 组合。
- [ ] 本地执行 `cd server && go test ./internal/httpapi ./cmd/relaynest ./internal/bots ./internal/delivery ./internal/retention`（按前置最终真实包定位，不凭空建目录）、`go vet ./internal/httpapi ./cmd/relaynest` 与 gofmt。记录真实环境；缺数据库故障/队列组合环境则对应验收 blocked，不用桩代替。
