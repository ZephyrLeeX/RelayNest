## 问题边界与选定方案

真实 RequestSecurity 从原库签发 actor 后，原库 generation reset 应使其失效。受信 Go 代码误将克隆外库 Write Tx 传给原 SessionStore 的公开 AuthorizeTx/RenewTx 时，旧代次可在外库被接受并提交 changes/续期。actor 私有绑定并不能证明裸 Tx 来源；没有证据表明网络请求可以提供 Tx。不能把正确同库测试通过或注释前置条件当作 F01 关闭证据。

采用 **SessionStore 持有自身 Store.Write 的受控闭包**，不引入 owner 数据库行或共享事务体系。候选入口形态：

```go
func (s *SessionStore) WithAuthorizedWrite(
    ctx context.Context, actor AdminRequest, fn func(*sql.Tx) error,
) error
```

名称可按现有风格微调；以下行为和边界必须保持：

1. 外部调用者只能传 actor 和业务回调，不能传事务、Store、owner 标志或事务工厂。实现固定调用 `s.store.Write`，在该回调入口调用私有 actor 鉴权；保留 `actor.store/issuer/issued`、公开 Session 防篡改及当前 generation/revoked/idle/absolute 检查。nil SessionStore、nil 回调按既有错误策略安全拒绝，不 panic、不调用业务。
2. 鉴权成功才调用 `fn(tx)`，其业务与 `changes.Append` 使用此唯一 Tx。回调错误原样向外传播；回调成功后在同一 Tx 再复核 actor 并续期，续期不越 absolute；任一错误、取消或提交失败全部回滚。Store.Write 返回 nil 后才能发布结果、明文凭据或成功通知。auth 鉴权/存储错误沿既有 ErrInvalidSession/ErrStorage 语义，业务/CAS 错误不可被误映射掉。
3. 删除公开裸 Tx `AuthorizeTx/RenewTx`，或改为仅 auth 内部私有 helper；不保留弃用包装/公开别名，也不导出接受任意 Tx 的旁路。内部列表和精确撤销只从它们自身 `s.store.Write` 调私有 helper，且不允许外部控制其 Tx。
4. 回调是受信 Go 业务代码，沿现有 Store.Write 规则同步使用所给 Tx、关闭 Rows、不自行 Commit/Rollback、不保留或另开事务。入口不接外部 Tx，故无需克隆数据比对或可伪造 owner 标志；不把本修复描述成隔离恶意回调、任意 SQL 或 unsafe 的沙箱。无需把 *sql.Tx 包成 SQL facade：现有 changes.Append 明确接 *sql.Tx，额外抽象会扩大共享契约范围。
5. 普通管理员业务回调不支持自撤 actor 后继续成功续期。设备自撤继续由 RevokeDeviceSession 私有路径处理：只接受本次精确自撤的 revoked=1，仍检期限/代次/身份，跳过续期并保留最终同一时刻双方检查；非自撤续期、目标到期屏障和 commit 后精确 ID hook 不变。不得把它机械搬进一般闭包而跳过尾检或提前发 hook。
