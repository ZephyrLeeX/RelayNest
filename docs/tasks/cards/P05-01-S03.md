## 工作与接口边界

1. 在既有 `Store.Write(ctx, func(tx *sql.Tx) error {...})` 的同一事务中完成授权/启用/能力复核、Bot 计数分配、消息 revision=1 插入、`changes.Append`、回填真实 created_change_seq、最小待办写入；任何错误向外返回，只有外层提交成功才发布结果。不得嵌套 Write、跨事务分段提交、事务内网络/广播或暴露失败候选序号。
2. 实际 Bot 接口为 `(*bots.Repository).Authenticate(ctx, botID, kind, secret)` 和 `bots.AuthorizeTx(ctx, tx, identity, botID, bots.Send)`；不存在 literal BotAuthenticate。凭据身份不可构造，sender 由受信身份决定；已认证身份仍须在业务事务复核停用、能力、凭据代次及 Bot 归属。Webhook 只复用获准 Send，不开放 Edit/Download。Bot lifecycle 已 done 是存储证据，不声称 Bot HTTP 已完成。
3. 提供可供 P05-02 在既有已授权写事务内复用的最小事务 primitive，避免 P05-02 为幂等重新拆事务；不冻结未经实现的函数签名。管理员方向仅作为受信调用方的同事务落库基础，sender 不能由不受信请求自由设置；未来正式入口须复用 auth.SessionStore.WithAuthorizedWrite 的同一事务及最终 G1 校验，禁止创建绕过实例/会话复核的公开管理员创建方法。此卡不新增管理员 HTTP/认证分支。
4. 最小 pending 入队直接留在 messages 包：管理员消息产生稳定 event_id 的 `message.created` 不可变快照及 pending delivery；应用消息不向自身伪造应用投递。必要初始 delivery 变更使用真实 changes 公共接口，created_change_seq 始终指向消息创建事件，不能混用排队序号/Bot 序号。不实现 callback/租约/ACK/重试/失败队列。
5. 同事务接受后续调用方提供的有界 device/session 目标并写最小 push pending，目标水位取本事务实际全局序号，不放正文/凭据；校验真实 session 的 Android 类型、device 绑定、撤销/过期/管理员代次。只提供持久入队基础，不自行发明设备订阅/注册选择规则；无已验证可用目标时为空，未来正式生产目标枚举、通知偏好/共享已读再判定和真实发送由 P07 接线。测试必须使用真实 session 行和显式目标写出待办，不能以空目标绕过父卡原子性验收。
6. 有限文本/无附件路径供仓储证明；非空附件及尚未接线的引用输入须显式拒绝，不能伪称已校验。完整幂等/输入验证与正式创建由 P05-02，历史引用/共享已读由 P05-03，编辑及附件由各自后续卡。UUID、安全随机错误、int64 计数溢出/受影响行异常显式失败；不更改 Bot 元数据版本来替代 bot_seq。

## 原验收映射与必跑检查

- [ ] **失败无半消息**：真实文件 SQLite 中，在计数分配后、消息后、消息变更/created_change_seq 后、delivery/push 入队后注入失败；跨连接查询并重开核对消息、Bot 计数、队列和 changes 全部回滚。包括至少一个真实 SQL 约束/Append 错误，以及上下文/锁失败；提交失败路径须有可复现证据，不能只证明回调错误。失败不返回成功结果。
- [ ] **序列单调**：同 Bot/多 Bot、同文件独立 Store 并发；已提交 bot_seq 每 Bot 唯一递增且互不串线，全局 change_seq 唯一递增；重开/删除后不退回，int64 上限失败原子。无需承诺无空洞或回滚候选不复用。
- [ ] **消息/待办/变更同事务**：分别覆盖管理员消息+delivery、应用消息+明确有效目标 push，并有同一事务组合所有必要行的底层验证；提交前他连接不可见，提交后齐全。核对 revision=1、created_change_seq 对应 MessageUpsert、稳定 event_id/不可变快照及实际目标水位；回滚时无孤立 pending/changes。
- [ ] **Bot 权限事务复核**：A/B 串用、receive-only、停用、API 重置/代次过期、Webhook 边界；身份认证后排队期间发生变更再提交必须拒绝，无序号/消息/队列残留。与 Bot 删除/停用/凭据重置组合不绕过既有约束。
- [ ] 必跑 `go test -count=1 ./internal/messages ./internal/storage ./internal/changes ./internal/bots`、`go test -race -count=1 ./internal/messages`、上述包 `go vet`、gofmt 与 `git diff --check`；记录真实工具/SQLite 版本、命令/结果和失败证据定位。
- [ ] 交接实际签名/错误、事务所有权、有限输入限制、S02 精确迁移及依赖 SHA；本地独立提交，另角色审计最终组合并集成后由调度置 done。
