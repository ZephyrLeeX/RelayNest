## 修复目标与边界

1. 三处模式均要求真正的字符串结尾，拒绝尾部 LF、CR、CRLF 及额外字符；使用当前 JSON Schema/正则工具链可支持的写法，不能只靠 Python 私有锚点修补共享 Schema。
2. `x-content-range` 对启用时的字符串完整识别两类既有格式：`bytes start-end/size` 或 `bytes */size`，数字仍仅 ASCII。两类都不能匹配时产生 `ValidationError`，不能解析失败后静默通过。不得 trim、删除控制字符后再接受。
3. 单区间保留 `0 <= start <= end < size`；`bytes */0` 和 `bytes */100` 等既有合法416值保留。206只允许单区间，416只允许星号形式；共同 Schema 允许两类合法形式。
4. 原消息/附件授权、跨 Bot 404、Webhook边界、幂等作用域/重放顺序、编辑CAS与callback快照契约全部保持。当前只修契约门槛，不宣称附件HTTP服务已修复或新增运行时需求。
