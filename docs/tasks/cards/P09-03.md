## 本任务工作

1. 先实现 T9.3 类型化插槽及静态装配、FCM实现：锁定 SDK/API、安全凭据加载、最小data载荷与错误分类；核心不含厂商请求字段。
2. OPPO实现须在 P02-05 现行鉴权/单推/错误表与实测证据、D1文案及D2/D3确认后独立派发；仅通用提示/必要元数据，不把业务消息模型传入适配器，不内置服务端秘密。
3. 输出区分平台受理、失效、暂态、限流、配置错及结果不确定；未知/格式/鉴权错误不能无条件删注册。目标失效按发送版本条件解绑单通道，不删除设备/会话。重试沿稳定提醒键，不在超时后跨通道补响；去重窗口由PoC验证，不承诺恰好一次。
4. 建议拆卡P09-03-S01（框架+FCM）与S02（OPPO）；registry由调度登记后各自实现/审计，父卡保留双适配及组合验收，详见 PUSH-PLAN-01 实施报告。未拆卡时也须分别报告两分支，不能用FCM通过替代OPPO。

## 测试与完成标准

- [ ] 不含正文/URL/秘密。
- [ ] 只按明确无效响应条件解绑对应通道/发送代次，不删除设备会话或新token。
- [ ] 暂态不删。
- [ ] 适配器桩覆盖限流/鉴权错误/未知/已受理后超时/注册轮换迟到失败；FCM与OPPO分别有版本及环境证据，OPPO缺环境明确blocked。
- [ ] 执行受影响检查，逐项报告命令/环境/结果；无条件运行时保留 `blocked`，不将必需验收记为通过。
- [ ] 提交仅本任务变更，交付基线SHA/实现SHA、diff摘要、证据路径和遗留问题；独立审计与集成完成后才可 `done`。

验证任务可交付负面结论，但不等于对应兼容门槛通过；调度依据报告把后续置 `blocked/needs_user`。只读研究也提交精简证据报告，不提交外部源码和原始凭据。

审计由另一个 agent 按 [统一协议](../WORKER_PROTOCOL.md) 执行，核对本卡范围、精确实现SHA、上述验收与越权/故障边界。审计不写代码；发现问题派修复卡，修复后重审。集成 agent 对最终变更组合做相关验证，总 agent 只调度。
