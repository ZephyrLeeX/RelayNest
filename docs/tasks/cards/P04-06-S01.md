## 工作与事务边界

1. Bot 创建/查询/编辑含名称、enabled、send/receive、版本与凭据公开元数据。PATCH 使用既定 expected_version CAS；Version 仍 JSON integer，从 1 起，不能套用全局 settings 专用 2^53−1 上限/字符串规则。
2. 两套至少 256 bit 随机、带公开标识的凭据独立生成与摘要持久化，摘要恒定时间比较；普通 Bot.credentials 仅 CredentialMetadata，无明文/摘要。创建结果严格保留 bot/api_token/webhook_key 三键；查询与编辑不再返回明文。本卡不实现重置。
3. 独立身份绑定 Bot ID/凭据种类/代次与 send/receive，验证停用覆盖全部授权；API Token 与 Webhook Key 不互换，Webhook 仅可发送，不能读/编辑/上传/claim/ACK/renew/管理。receive 不授创建/编辑/跨 Bot。为后续 Bot 写操作提供同事务重新核对身份、代次、enabled/能力的接入能力，禁止仅依赖请求开始时快照。提供后续消息/投递代码接入约束，不实现其业务。
4. 复用 storage.Store.Write 的短事务：Bot 写入、版本递增及对应 changes 追加必须原子提交；任一失败全部回滚，不能留待 P06 补历史。复用已冻结的共同追加实现，必须接受调用方事务；不嵌套提交、不跨网络等待持有事务。
5. 冻结字面值为 SyncBotUpsert 的 `bot.upsert`（不是 bot.updated），关联 Bot；删除分支为 SyncBotDelete 的 `bot.deleted`，关联 id/version/deleted_at。本卡不实现删除；不得给既有 changes.bot_id 添加级联删除外键，后卡必须保留墓碑。
6. change_seq 使用既有全局 AUTOINCREMENT，不另设 Bot 私有变更序列；epoch 沿用 system_state 初始化值，不因 Bot 写入重置。持久层 int64 与公共 Sequence 的规范十进制字符串通过共同契约转换，不能与 Bot.version/bot_seq 混用。
7. 迁移夹具随真实迁移集合维护，人工升级迁移使用动态下一编号，避免固定 0004 撞号；保留失败回滚、持锁等待、checksum、epoch 稳定、重复迁移和版本断言强度。不改迁移器或通过删除断言放行。
