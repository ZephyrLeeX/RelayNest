## 工作与验收

- [ ] 补 `GET /devices`、`DELETE /devices/{id}/session`：管理员Bearer/Web Cookie读取，Cookie撤销需CSRF+同源；列表不回显凭据/推送token。撤销对应会话全部通道/WS，注销仍只当前会话，不影响其他设备或Bot凭据；未知/无权设备与权限错误依既有约定。设备会话元数据复用既有模型，不接受注册接口指定其他设备/会话。
- [ ] 补 `PUT /devices/current/push` 通道无关注册，确定最小恢复读取/条件删除操作及Schema（当前会话限定，常规命名可自行决定）：每provider单独 token、registration_version、expected_version、服务端updated_at、会话代次隔离；省略其他通道保持。相同注册版本同内容幂等，旧版/同版异值冲突；初始注册/缺失记录的CAS值、删除后迟到写入防护和重登录隔离必须明确，不能用删除记录丢失版本屏障。
- [ ] 条件删除只解绑发送快照的provider/注册代次；轮换迟到UNREGISTERED、网络错误、未知结果不能删新token/其他通道/设备会话/通知偏好。客户端条件删除与服务内部发送失败解绑区分；不向客户端暴露后台job操作或厂商错误串。
- [ ] 补 `PUT /devices/current/notifications` 及当前配置恢复读取，设备全局/Bot开关、DND时区/跨午夜时段、预览、notify_channel=fcm|vendor|none与具体notify_provider分离。settings_version服务端单调、expected_version CAS，冲突最新版本及重读方式完整；注册可用不自动启用模式。vendor须有效注册且满足平台前置，未满足可表达/拒绝，不静默回退；非法provider/模式组合拒绝。各类版本不能混作客户端时间。
- [ ] S01的设备相关设置变更分支、版本应用/当前设备恢复读补齐；不得把别的设备偏好在同步中覆盖当前设备。服务端时间、配置/注册版本耗尽与错误处理保持既有风格，不回绕、不部分提交。
- [ ] D1固定title「RelayNest 有新消息」+content「打开 RelayNest 同步查看」，仅适配边界说明，不添加厂商payload接口。D2显式可选vendor、首次FCM/补偿、切换仅未来新事件、旧job失效/外发在途残余、超时不跨通道补响、配置收敛允许漏提醒且仍补偿数据。D3仅vendor接受离线DND/已读/删除/退出/切换后撤回限制；FCM继续T9.2自绘、去重/共享已读/预览/DND，不扩大豁免。
- [ ] 用可审查夹具覆盖多通道并存、局部更新、同值幂等/旧版/同版异值/配置CAS冲突与恢复、token不回显、旧失败解绑/迟到注销回调、会话撤销后的重登隔离、非法provider及其他设备越权。job快照的会话代次/用途/水位/provider/注册版本/配置版本/稳定提醒键/过期时间及发送前后条件更新写明确说明；不是新增HTTP工作队列。
- [ ] 所有新增恢复读/条件删除路径、权限、状态码、Schema与同步扩展在交接枚举；真实多worker/SDK注册/平台展示/真机DND等NOT_RUN，不把结构通过写成G-OPPO通过。旧契约非回归后移交S03。
