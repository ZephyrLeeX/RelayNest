# P04-07-S02 Bot 删除确认与基础删除事务

## 前置与目标

- 父卡：[P04-07](P04-07.md)；依赖：P04-07-S01（独审集成）。完整职责仅为名称/版本确认、凭据与 Bot 基础删除、typed 删除标记和永久级联事务接入位置。
- 最小上下文：T4.3、PRD3.1、OpenAPI `DeleteBotRequest/deleteBot`，S01 最终交接；3–5主要文件 `models.go/lifecycle.go/repository.go` 与对应 bots 测试。`changes.BotDeleted` 为既有类型，只读复用。

## 范围与实现约束

- 允许 `server/internal/bots/**`；仅经证据确认确需新增持久数据时，才可在 `server/migrations/**` 新建迁移，不重写 0001–0004，不预占编号。实施者先向调度报告必要性与串行集成顺序；无必要不加迁移。
- 在同一受控写 Tx 中读取当前名称和版本，校验 `confirm_name` 与 `expected_version`；不采用请求中的未核验目标。版本冲突、名称不符、缺字段/空名、目标不存在、耗尽全部无部分写。
- 基础删除仅覆盖 Bot/两凭据及管理同步删除标记，沿用 S01 事务扩展约束；队列/消息/附件的完整级联明确归 P06-07。需要确认的调用才进入写操作；取消确认不调用仓储，不写 changes 或续期。
- typed BotDeleted 标记应能在实体删除后继续按既有 changes 契约读取；与基础删除、扩展点、管理员续期同成同败。不得只因 FK cascade 已删凭据便声称消息/受保护队列已删除。
- 新方法不得自行挂到 HTTP 或在正式装配中把空级联当永久删除；未来 S03 必须依赖 P06-07 完整组合。基础测试用注入失败证明 Tx 边界，不以空桩证明生产级联。

## 验收与检查

- [ ] 正确双确认删除本 Bot 与两凭据，删除后旧 Identity 拒绝；另一 Bot 与其凭据/changes 均不误删。
- [ ] 取消、不匹配、过期版本、并发编辑/删除、版本耗尽无额外副作用；成功删除具有可读的既有删除标记。
- [ ] 基础删除前后扩展/changes/提交故障均整体回滚，不能留下已失效凭据但 Bot 未删等中间状态。
- [ ] 本地 Go 环境执行 `cd server && go test ./internal/bots ./internal/changes ./internal/storage`、`go vet ./internal/bots` 与 gofmt；若新增迁移，补真实旧库升级及空库测试。记录版本/结果，明确完整删除未集成。
