## 工作

1. 接入 GET/POST `/api/v1/admin/bots` 与 PATCH `/api/v1/admin/bots/{id}`，遵循冻结 BotPage/CreateBotRequest/CreatedBotResponse/PatchBotRequest/Bot 和错误契约；GET 是列表，不能擅自增加详情路由。PATCH expected_version CAS，服务端版本/事务沿 S01；不在 handler 二次非事务补 changes。
2. 管理员 Bearer 与 Web Cookie 走真实会话验证：过期/撤销拒绝，Bot API Token/Webhook Key 一律不授管理权限。Web 写操作落实会话 CSRF 与 Origin/Referer/可信代理外部 scheme/host/port；P04-03 完整安全前置不可被 helper 单测代替。
3. 创建仅在成功响应返回本次明文，精确顶层 bot/api_token/webhook_key；GET/PATCH 只返回凭据公开 metadata，响应 no-store，错误/日志不泄露密钥或摘要。响应丢失不能通过 GET 找回明文；不增加重置路由。
4. 在真实 router/中间件/数据库组合上验证跨 Bot/跨路由拒绝与 receive-only 不能发送。已有真实 Bot 业务路由按实际实现执行；本卡不实现尚不存在的消息/claim/ACK 路由。未存在的 Bot 路由只能证明未知路由不能落到管理 handler，独立 send 拒绝由 S01 真实授权集成测试覆盖；报告明确边界，不能把 404 冒充消息业务验收。
5. 向 P05/P06 交接 S01 的独立身份及提交前再校验接口、停用覆盖和两种凭据分离。未来消息/投递路由仍须以其实际业务 HTTP 另验收，不把权限单测充当未来路由已实现证据。

## 明确不做

不实现 DELETE、凭据重置/清空、消息/附件/队列管理、轮询/租约、Web 历史或 P06 其他管理功能；不改 RelayShelf/MP，不执行业务命令/MCP，不派子 agent、不推送。

## 测试与完成标准

- [ ] 三路由通过真实管理员 Bearer/Web Cookie 成功；无凭据、过期/撤销会话、两类 Bot 凭据（各 Bot/各能力组合）访问三路由均拒绝，不意外回落静态 HTML 或其他 handler。
- [ ] Web POST/PATCH 的缺失/错误 CSRF、跨源/Referer 回退、代理信任及端口/scheme 组合覆盖；Android Bearer 按既定策略执行。有效管理员 Cookie 写成功，不能只测所有请求失败。
- [ ] 两个 Bot 的身份隔离与 receive-only 发送拒绝有真实 S01 授权及 HTTP 管理拒绝组合证据；未来未实现消息 HTTP 列明 not_run/后卡约束，不伪报通过。
- [ ] 创建明文仅成功创建响应可见；列表/PATCH/错误/日志及数据库无明文，普通 Bot.credentials 无摘要；字段、CAS 冲突、no-store 和错误码符合 API。
- [ ] 父卡五项原验收逐条映射最终组合 SHA/证据，完成受影响格式/静态/Go 测试；未满足父卡必需项保持 blocked，不以子卡报告通过自动置父 done。
- [ ] 单独本地提交，交基线/实现 SHA、S01 与管理员/安全消费 SHA、diff、命令/环境/结果/遗留；独立 A/I 后子卡才能 done。
