## 工作与边界

1. messages 保存 UUID、bot_id、bot_seq、created_change_seq、sender、revision、格式/当前正文/按钮、引用与原始引用 ID、时间；UNIQUE(bot_id,bot_seq)，已有 Bot FK 与删除行为一致。可空当前引用 SET NULL，原引用 ID 保留，不能以引用 FK 永久保护源消息。序号 SQLite integer 上限与 JSON 十进制字符串、整数版本保持已冻结区分；created_change_seq 最终须关联真实创建事件，不生成另一套全局计数。
2. 创建父卡所需最小 deliveries 与 push_jobs：delivery 的稳定 event_id 唯一、bot 归属、不可变载荷快照、pending/state_version、attempt/generation、排队序号和到期时间；租约/完成字段如最小约束需要可空，但不实现迁移到 leased 或其他状态。push 待办保存 device/session 绑定、目标全局序号、pending、尝试与下次执行；复用真实 sessions，不能臆造已有 devices/registration 表。只建必要索引/约束，队列状态类型遵从设计；后续 P06/P07 扩充字段另走各自串行迁移。
3. 新 messages 模型只提供 S03 所需持久数据和 pending 输入；不得创建完整同步/HTTP DTO 或冻结新的公开业务签名。投递快照遵守 MessageDeliveryEvent，push 无正文/凭据。无 interaction、附件、业务幂等、read-state 扩建。
4. 迁移不调用 InitInstanceIDTx，不创建/修复/旋转实例 ID 或 sync_epoch，不改 S01 的初始化次数/迁移挂钩；升级仅消息结构。实例 ID 缺失/损坏沿用最终 S01 失败关闭，不能以新迁移补齐。
