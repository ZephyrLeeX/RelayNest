## 本任务工作与冻结契约

1. 依据 OpenAPI servers=/api/v1，挂载 POST /api/v1/auth/login（login，security=[]）、GET /api/v1/auth/session（getSession，AdminBearer 或 WebCookie）、POST /api/v1/auth/logout（logout，AdminBearer 或 WebCookie+CSRF，成功 204）。不另造 /login、/admin/auth 或无前缀别名。
2. 登录消费 LoginRequest：username/password/client_type/device_name；Android 另需 device_id。拒绝未知字段，复用冻结请求限制/统一错误；唯一管理员凭据错误统一 401 AUTHENTICATION_FAILED，不泄露账号存在性或密码摘要。使用 P04-01 实际 Argon2id 校验，调用 S01 时保留被验证代次以防重置竞争。
3. LoginResponse：Web 为 WebSessionResponse(session, csrf_token)，仅 Cookie 携带会话；Android 为 AndroidLoginResponse(session, access_token, token_type=Bearer)，不设置 Cookie。SessionResponse：Web 同前，Android 为 AndroidSessionResponse(session)，不重复返回 access_token。Session 包含 id、administrator、client_type、device_id、device_name、idle_expires_at、absolute_expires_at，无摘要/密码。
4. Web Cookie 名 relaynest_session，HttpOnly、SameSite=Lax、Path=/api/v1，外部 HTTPS 时 Secure；注销仅清当前 Cookie（Max-Age=0）与当前会话，调用 S01 撤销语义，不影响其它设备/Bot。双端受保护/认证响应按冻结契约 no-store，凭据及 csrf_token 不写日志。
5. 最低安全要求在本卡完成：Web 登录同源 Origin，Web logout 的会话 CSRF（X-CSRF-Token）及同源 Origin/Referer；认证按 AdminBearer/WebCookie 的实际类型验证，Bot 凭据不能进入。不得为了等待 P04-03 而放行失败/缺失安全校验，不信任任意转发头决定来源或 HTTPS。
6. 复用已集成 P04-03-S01 的来源配置及解析/校验结果，注入三条认证入口；不在 auth 中复制 Host/forwarding 解析。来源校验错误须映射既有 API 错误，不继续建立会话或写 Cookie。P04-03 仍负责全局 Cookie/CSRF/Origin/可信代理策略及跨业务验证，P04-04 仍负责登录并发/速率限制和公共脱敏日志体系。本卡仅三条路由必需安全适配；来源模块缺陷先报告调度，不以任意 Host、自动信任环回/内网、默认域名、关闭来源校验或推迟最低安全保护补位。运行配置读取/注入方案及影响见 [规划报告](../reports/P04-03-PLAN01-implementation.md)，必须提供实际启动接线证据。
7. 双端 HTTP 驱动完整生命周期：登录→当前会话/续期→重启→到期或注销→拒绝旧凭据，并覆盖管理员重置/登录竞争与其它设备隔离。复用 S01 并发证据，补真实 HTTP→数据库组合检查；未来 WS/推送未落地时明确未验证，不伪造关闭结果。
