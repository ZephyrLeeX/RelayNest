# P04-07-S01 Bot 凭据轮换与状态事务扩展点

## 前置与目标

- 父卡：[P04-07](P04-07.md)；依赖：P04-06、P04-07-PLAN01，均须独审集成。下一张直接实现本卡，不再递归规划。
- 完整职责：在现有 Bot 仓储中实现两凭据独立轮换，并使现有启停/Patch 和 API 凭据轮换可在同一写事务调用后续队列扩展点。
- 最小上下文：T4.3、PRD3.1、OpenAPI `resetAPIToken/resetWebhookKey`（只读）、P04-06-S02-I01；局部 `repository.go/models.go/authorization.go`、对应 bots 测试。沿用 Authenticate/AuthorizeTx，不增加未来 G1 header 或新会话签名。

## 范围与实现约束

- 允许 `server/internal/bots/**`，主要文件预计 `models.go`、`repository.go`、新增 `lifecycle.go`、`bots_test.go`/生命周期测试（3–5个）；不改 HTTP、SQL、API、auth/storage。
- 沿用 `WriteFunc`/Store 同一 Tx；业务变更、凭据摘要/代次、Bot 版本、typed changes 和调用方会话续期同成同败。返回新明文必须在提交成功后；普通读取/日志/changes 不出现明文或摘要。
- 仅推进所选凭据 generation，另一凭据的 ID/代次/摘要和授权保持不变；用现有安全随机生成逻辑。API 旧 Identity 在重置提交后通过 AuthorizeTx 拒绝，Webhook 轮换不触发 API 租约动作。
- 复用既有 enabled/CAS/能力规则；扩展点仅传入本次受控事务及明确 Bot/动作信息，禁止嵌套写事务、网络等待或自行提交。这里只固定同事务职责，不预造 P06-07 的未来函数签名。
- 任何 Bot version、credential generation 或 changes 计数耗尽均拒绝整笔操作，不回绕/归零；内部错误沿现有约定，HTTP 新错误映射由 S03 门槛处理。随机失败、目标不存在、扩展点/changes失败均不得部分修改。

## 验收与检查

- [ ] 两种轮换各有 A/B Bot 与另一凭据不受影响的证据；新值仅成功调用一次返回，失败不返回可用秘密。
- [ ] 旧 Identity 认证完成后再重置/停用，最终业务 Tx 的 AuthorizeTx 拒绝且无业务写/changes；先合法提交的操作可成功，不能声称追回已返回数据。
- [ ] CAS 冲突与 int64 上限、随机/扩展点/changes 故障后 Bot/两凭据/changes 全无部分提交；启停扩展点失败同样回滚。
- [ ] 停用阻止收发，恢复沿原能力；Webhook reset 不触发 API 专用扩展点。
- [ ] 本地 Go 环境执行 `cd server && go test ./internal/bots ./internal/changes ./internal/storage` 与 `go vet ./internal/bots`、受改 Go 文件 gofmt；记录版本。没有消息/租约矩阵，不宣称 P06-07、真实 HTTP 或完整删除通过。
