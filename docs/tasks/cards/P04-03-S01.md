## 本任务工作与交接约束

### 1. 权威配置与来源比较

- 用显式配置的单个外部 HTTPS Origin 作为同源比较基准。它来自部署方提供的值，经构造器验证后不可由请求覆盖；不从任意 Host、Origin、Referer、监听地址、环境猜测或转发头生成信任基准。真实域名/端口与代理清单待部署前提供，不要求现在取得，不预填真实资源。
- Origin 为 scheme/host/有效端口三元组：scheme/ASCII 主机名大小写归一，HTTPS 缺省端口为 443，显式 443 等价，非缺省端口必须精确匹配；IP 使用标准库规范化，IPv6 方括号及端口须正确解析。只接受无 userinfo/path/query/fragment 的 HTTPS Origin；拒绝通配符、空主机、控制字符、非法端口、混淆 authority、`null` 或多值。IDN 用部署方显式 A-label，不新增 IDNA 依赖，不以 DNS 查询证明同源，不擅自把尾点主机或域名别名合并。
- 公网 HTTPS 要求不变；本地单测也显式指定测试 HTTPS Origin，以可信代理 HTTP 入站模拟 TLS 终止，另用 TLS 请求验证直连；不新增 HTTP Web 登录例外。

### 2. 直接 peer 与转发头

- 只用 net/http 的直接连接 `RemoteAddr` 判断代理信任，解析 IP:port，IPv4-mapped IPv6 统一处理；解析失败拒绝来源解析，不从任何头修复 peer。配置只接受显式 IP 或 CIDR，无隐式环回、私网、监听地址或任意代理默认值；空列表表示没有可信代理。禁止主机名代理与全地址段兜底。
- 非可信 peer：完全忽略所有转发头；候选外部来源仅来自实际 TLS 状态与 `Request.Host`，客户端地址为 peer。候选必须与配置 Origin 一致，Host 不是新信任基准。伪造头不能将不匹配来源/HTTP 请求变成合法 HTTPS 请求，也不能改变客户端 IP；合法直连附带伪造头仍按直连值判断。
- 可信 peer：采用最小单层覆盖协议，外部代理须覆盖 `X-Forwarded-Host`、`X-Forwarded-Proto`、`X-Forwarded-For`，各恰好一个值；Host 为单一 authority（含所需外部端口），Proto 为 `https`，For 为单个 IP。拒绝重复头、逗号列表、多 hop、空值、畸形或部分缺失，不猜选首项/末项。不取 URL.Scheme、X-Forwarded-Port 等替代字段作来源或 Secure 判据。
- 可信 peer 的上述三头均不存在且无 `Forwarded` 时按直连 TLS/Host 规则处理；一旦出现本协议任一头必须完整验证，不允许失败后回落直连。可信 peer 带 RFC `Forwarded` 时拒绝来源解析，避免与本协议混用；本卡不实现两套协议协商或多层代理链。非可信 peer 的 `Forwarded` 同样不作为输入。
- 可信转发候选仍须匹配配置 Origin；安全标志只由验证成功后的外部 HTTPS 结果产生。转发 Host/Proto 冲突、端口差异、声称 HTTP 或客户端 IP 畸形均拒绝；代理到 Hub 的内网 HTTP 不得使有效外部 HTTPS Cookie 丢失 Secure。上游代理覆盖行为需部署时验证，本地反例不是部署验收。

### 3. 浏览器来源校验与结果输出

- 提供无会话依赖的同源校验能力：登录要求恰好一个合法 Origin；写操作有 Origin 时验证它，缺失时才允许合法绝对 Referer 提取 scheme/host/port 后比较，二者均缺失拒绝。Origin 不合法或跨源不能借合法 Referer 绕过；二者均有时须无冲突，畸形值拒绝。Referer 的 path/query 不参与同源，userinfo/fragment/非法 authority 拒绝，禁止将整串 Referer 回写日志。
- 拒绝 Origin `null`、多 Origin、重复头、非法 scheme/host/port；来源均与同一配置基准比较，不采用仅域名或字符串前缀匹配。登录规则不替代写操作的会话 CSRF，模块不判断 Bearer/WebCookie/Bot 身份。
- 成功输出应足以区分配置基准、已验证外部来源/HTTPS、直接 peer、有效客户端 IP 与是否使用可信转发；失败显式返回错误，不以空值/安全默认值继续。不得泄露请求头或完整 Referer。实际 Go 类型、函数名与错误类型由实现确定，在独审/集成后以精确 SHA 交接，不在规划中虚构已冻结函数签名。
