## 发现 A01-01：严格 JSON 解码接受未声明的大小写别名字段

- 严重度：P2；结论：必须修复后重审。
- 位置：`server/internal/httpapi/bots.go:86`～`92`，关联输入模型及 CreateBot/PatchBot；冻结契约 `server/api/openapi.yaml:2997`（Capabilities）、`:3237`（CreateBotRequest）、`:3252`（PatchBotRequest）。这些对象均限定精确属性并 `additionalProperties: false`，创建与能力对象另有精确必填键。
- 触发条件：具有有效管理员权限的请求使用 `Name`、嵌套 `Send` 或 `EXPECTED_VERSION`/`Enabled` 等未声明键。`DisallowUnknownFields` 仍按 Go JSON 的大小写不敏感字段匹配解码；前置 RawMessage map 只查 null，没有校验精确键。因此未声明键被当成合法字段，精确必填键缺失也可通过。
- 影响：无效输入实际创建/修改 Bot、版本和 changes，并成功续期会话；属于冻结 HTTP 契约和“无效请求无副作用”验收缺口。未发现由此绕过管理员认证或 CSRF。
- 独立复现：临时 overlay 复制固定实现的 `main_test.go`，只追加 `TestAuditBotAliases`，复用现有真实 TLS/生产授权/SQLite fixture。每例在请求前后比较 fixture 的全库快照，不输出秘密。

| 同 POST，`{"name":"alias","enabled":true,"capabilities":{"Send":true,"receive":false}}` | 拒绝嵌套未声明键，无写入 | 201，`database_changed=true` |
