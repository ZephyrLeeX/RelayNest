3. **权威与信任边界**：显式单 HTTPS Origin 作为不可由请求覆盖的比较基准；真实直接 peer IP/CIDR 决定代理信任，无自动环回/私网信任。非可信 peer 忽略转发头，仅实际 TLS/Host 匹配配置；可信代理只消费覆盖式单值 X-Forwarded-Host/Proto/For，缺失、畸形、重复、多 hop、冲突和 Forwarded 混用均失败，不回落修复。
4. **来源与 Secure 一致**：scheme/host/有效端口比较、默认 443 等价、IPv6/非法 authority、跨源/端口与重复头反例均明确。可信代理内网 HTTP 仍输出验证后的外部 HTTPS；伪造头不能改变非可信连接的 Origin、客户端 IP 或安全标志。可信 peer 无全部转发头时，仅匹配配置的真实 TLS 直连可成功，不能让内网 HTTP 退化通过。
5. **浏览器与原生通道隔离**：S01 是无会话纯模块，浏览器来源校验能力不会自动施加到每条路由。S02 第5项明确 Web 登录与 Web logout 要求，原双端凭据规则继续约束其“注入三条认证入口”的调用方式。冻结 LoginRequest 描述限定 Web 登录 Origin；logout security 将 AdminBearer 与 WebCookie+CSRF 分开。实施时按 Web/Cookie 通道调用，不能把 Android Bearer 强制成浏览器 Origin/CSRF 客户端。规划没有改变此契约。
