## 独立核查

1. **配置与规范化 PASS**：构造器只接收显式单 HTTPS Origin，私有字段保存规范化值与复制后的代理前缀；nil/零值 policy 不可使用。scheme/ASCII host 大小写归一、缺省/显式 443 等价，非缺省端口精确比较；域名标签、IP、带括号 IPv6、mapped IP、有效端口均核查。userinfo、path/query/fragment、控制字符、反斜线、畸形 authority、空值、通配符、null、多值拒绝；尾点保留，不做 DNS/IDNA 推测。
2. **直接 peer PASS**：仅解析 `RemoteAddr` 的 IP:port，拒绝非法 peer/zone；只按显式 IP/CIDR 信任，无默认 loopback/私网/全地址段。mapped IP 转 IPv4，mapped CIDR 长度不超过 96 时拒绝，否则减去 96 转等价前缀后 Masked；不会扩为 IPv4 全网。不可信 peer 完全忽略 forwarding 头，要求实际 TLS 与 Host 匹配配置，ClientIP 始终为 peer。
3. **可信代理 PASS**：三头各单值、完整覆盖，Proto 精确 `https`，For 单 IP；缺项、重复、逗号多 hop、非法值、Host/端口冲突和任意 `Forwarded` 拒绝。失败没有直连回退；只有三头与 Forwarded 都缺失才验证直接 TLS/Host。不读 URL.Scheme 或 X-Forwarded-Port 作为替代依据。可信 HTTP 入站成功后才生成 HTTPS/Secure。
4. **浏览器来源 PASS**：登录必须 Origin；写操作仅 Origin 缺失才回退 Referer；出现的 Origin/Referer 均须合法且匹配同一配置。坏 Origin 不能用好 Referer 覆盖，双头冲突拒绝。Referer path/query 不参与比较，允许其中合法逗号/转义，拒绝 userinfo/fragment/非法 authority。缺头、重复、空头、null、多 Origin、scheme/host/port 差异均有反例。
5. **输出与职责 PASS**：三个固定 sentinel 不包含配置、原始头或 Referer；每个失败分支返回零 RequestSource。成功输出 canonical 配置/候选 Origin、HTTPS/Secure、DirectPeer/ClientIP/Forwarded。模块无日志、SQL、会话、CSRF、认证或启动接线；Android Bearer 后续可调用 Resolve 而不强加浏览器头。
6. **交接 PASS**：实施报告提供 NewOriginPolicy、Resolve、ValidateLogin、ValidateWrite 的实际接口、构造/注入示例、失败先检查错误的消费要求及代理覆盖前提；未把本地 fixture 写成真实代理或会话验收。
