## 实际接口与风险核对

- 实际输入为 `DeleteRequest{ConfirmName string, ExpectedVersion int64}`；`Delete` 与 `DeleteWithWrite` 返回既有 `changes.Sequence`。空 ID/名称、非正版本、nil write 在进入写操作前拒绝。没有新增取消参数或 HTTP 接口；取消确认的契约是调用方不调用仓储。
- 受控 WriteFunc 同 Tx 读取真实 Bot，再检查 expected_version、逐字名称、MaxInt64；依次执行 DeleteBefore、带 id/version/name CAS 的 DELETE、DeleteAfter、typed BotDeleted，最后由调用方续期并提交。Before 是 Tx 当前公开 Bot；两个删除动作 After 均为零值，明确实体不存在。受信扩展只能同步使用同一 Tx，既有约束禁止自行提交、网络等待或嵌套写。
- 两凭据按既有 `bot_credentials` FK ON DELETE CASCADE 同事务删除；changes 表没有 Bot 外键，终态 ID、version+1、UTC 删除时间删除后仍可读取。标记仅是既有元数据，并非完整同步投影或消息墓碑。公开 Bot/扩展元数据不含凭据明文或摘要，删除不申请随机数。
- 初始确认发生在事务内，最终 CAS 再核名称及版本；独立 overlay 补证同 Tx 的前置扩展改名也返回 ErrConflict 且回滚。耗尽在加一前拒绝，最后有效版本及全局序号可到 MaxInt64，不回绕；全局序号已耗尽导致整体回滚。
- 失败均返回零 Sequence；storage 的 defer Rollback 与真实 Commit 错误传播覆盖实体、凭据、hook、changes。auth.WithAuthorizedWrite 先鉴权、业务回调后续期，同 Tx 提交；续期或提交失败不发布成功结果。未扩大受信扩展的权限模型。
