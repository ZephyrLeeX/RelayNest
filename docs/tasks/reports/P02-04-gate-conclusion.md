## 场景延迟矩阵（data-only；normal=默认优先级）

| 场景 | normal | HIGH |
| --- | --- | --- |
| 前台亮屏 | 94–137ms | 0.5–4s |
| 深度 Doze（受控 force-idle） | **挂起**：一条 >6 分钟始终未达，`onDeletedMessages` 未触发 | **118ms 穿透**（到达时设备仍 IDLE、灭屏） |
| 灭屏自然 Doze | 187.5s（解锁回前台 0.8s 内补达） | 未单测（同左通道） |
| 进程被杀（未开自启动） | 不投递 | **不投递**（干净条件 20s+ 无拉起） |
| 进程被杀（自启动已开） | 未单测 | **5s 内进程拉起 + 送达** |
| force-stop | 停止态完全不可达，重开后 110ms 补偿同步 | 同左 |
| 重启（不碰应用） | — | 代理开：通道恢复后送达（本次积压 167s）；代理关：滞留服务端 |
| 锁屏页（亮屏未解锁） | 积压不冲刷 | 可达（Doze 灭屏下已证） |

积压冲刷规律（三次复现）：被扣消息**从不随回前台自动冲刷**，只随通道事件（新消息到达/代理恢复/解锁时的通道重建）补达。补偿设计不得依赖积压冲刷。

## 实现约束（交 P09 落地）

1. **优先级**：默认 normal；HIGH 仅用于确需及时用户可见通知的场景（已证穿透 Doze 118ms 与 normal 挂起的对照）——维持 T9.1 约束。
2. **服务端**（P09-03）：旧 token 实测返回 **HTTP 404 `NotRegistered`/`UNREGISTERED`**，仅此错误可删设备记录；网络类失败不删。Token 在卸载重装时必换、重启/进程死亡不换。
3. **设备引导（onboarding 必做）**：引导开启 ColorOS「自启动」权限——未开时进程死后推送唤不醒（比 Doze 更大的可用性风险）；引导代理/Google 可达网络为推送前提。
4. **降级模式**：无 Google 网络时推送退化为补偿-only（打开即同步 + 周期），产品文案与预期管理按此描述，不算故障。
5. **不得依赖**：积压消息自动冲刷（回前台不触发）；`onDeletedMessages` 的及时性。
6. **自动化注意**：ColorOS 拦截 adb 静默安装（需手动/深度扫描）；真机 E2E 编排需预留解锁与无线调试 mDNS 的手动环节。

## 风险与未尽事项

- ColorOS 长窗速冻/深度睡眠未测（需数小时）：若产品反馈延迟投诉集中于此，P11 联调时补测。
- 切网（Wi-Fi/蜂窝）未测（控制通道与 Wi-Fi 同路；蜂窝无代理时 Google 本不可达）。
- normal 消息在 Doze 中的服务端保留/TTL 行为未定论（301 现象），P09 可用 TTL 参数化复测。
- 通知权限拒绝、登录/退出语义：属 P09-01/P09-06。
