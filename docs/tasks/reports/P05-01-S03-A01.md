## 审阅结论

- 唯一应用包装器在真实 Store.Write 内调用 AuthorizeTx(Send)，复核受信身份的 Bot 绑定、启停、能力、凭据身份及代次。排队后停用、降权、代次变化、删除，API/Webhook 跨 Bot、零身份及旧能力快照均有拒绝证据。Webhook 仅复用 Send。
- bot_seq 使用 SQLite int64 并显式检查上界和受影响行；消息 revision=1，不修改 Bot 元数据 version。复用公共 Append 后回填真实 MessageUpsert 序号；DeliveryUpsert 的序号仅作为排队及 push 最终水位。所有错误向外传播，包装器连 COMMIT 失败也返回零 Created。Tx primitive 返回候选且明确要求调用方传播错误及提交后发布。
- 管理员方向仅提供受信 Tx primitive，固定 administrator sender，并复核 Bot 启用及接收能力；没有新增管理员 HTTP 或独立授权包装器。正式入口仍必须使用 WithAuthorizedWrite 同一事务及最终 G1，当前测试不证明该接线完成。
- delivery 同事务生成稳定 event_id、完整十二键 message.created 快照；bot_seq 为十进制字符串、revision 为整数、UTC 时间、空附件/按钮和 null 引用符合有限文本路径。SQL 固定初始 pending/1/0/0 并阻止快照变更；正文后来修改不改变载荷。应用消息不产生自身应用投递。
- push 使用真实 Android session/device 绑定，检查撤销、idle/absolute 期限及管理员代次；目标有界且禁止重复。持久待办只含目标、水位及扫描元数据，无正文、URL、凭据。有效显式目标参与管理员和应用事务验证，未以空目标绕过验收。Bot 删除级联消息/delivery、保留全局提示；session 删除清理 push。
- 独立检查测试断言：真实文件、多连接及重开覆盖计数、消息、Append/回填、delivery/push、真实 SQL 唯一约束及受影响行错误；比较消息临时 NULL、各实体计数、changes 水位、Bot 计数及 sqlite_sequence，失败无残留。延迟 FK 在回调成功后真实拒绝 COMMIT，不是回调错误冒充。32 条同/多 Bot、同文件独立 Store 并发、重开/删除后单调与 int64 上界均覆盖；上下文及真实写锁失败不泄候选。
