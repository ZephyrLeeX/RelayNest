## 崩溃边界与后续限制

- 对进程内并发和原子可见性，锁及同目录原子 rename 有代码与 JVM 证据；清除的文件删除/键删除不是跨文件系统与 Keystore 的单一事务。进程在任一步中断，不会读取半条明文记录；写入 rename 前仍是旧记录或无记录，rename 后为新密文；删除文件后中断不会通过正式路径返回残留键。未做进程杀死或真实断电试验，不能将上述静态推导写成实测。
- atomicWrite 没有目录 fsync；fd.sync 只覆盖临时文件内容，因此不能保证突然断电后目录项一定保持最新 rename/delete。进程异常还可能留下不被恢复路径扫描的加密临时文件，位于不备份目录。现实施报告没有宣称断电持久性；Android 文件系统的重复替换/异常删除/断电行为仍需设备验证，不据 WSL 结果作额外保证。
- AndroidKeyStore 真实执行、密钥设备失效、硬件支持、卸载重装和备份/迁移均 NOT_RUN。JVM 注入 AES 密钥只能证明 GCM 封装和控制流；不解除 S04/最终设备验收门槛。
- restore 只返回 Session.id 与 credential；S03 必须调用真实 session 端点校验后发布认证状态。存储锁不能把 isCurrent 与随后 UI 发布变为同一事务，S03 还须串行控制状态并在响应提交前校验票据；每次重试需新 begin。
- 锁和代次仅同进程；现 Manifest 无跨进程组件。后续增加进程需重新审查，并非当前范围扩展。
- endpoint 绑定不是服务器实例身份；D01 同地址部署替换决策、完整设备撤销与父任务组合验收继续保留，未新增身份 API 或策略。
