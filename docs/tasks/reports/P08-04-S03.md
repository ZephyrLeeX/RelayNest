## 范围与实现

仅新增 `feature/auth/AuthRepository.kt`、`AuthViewModel.kt`、`AuthScreen.kt` 和对应 `AuthRepositoryTest.kt`；修改现有 `MainActivity.kt`、`app/build.gradle.kts`，加本报告。主要实现共五文件。未改 network/security 源码、API、服务端、Manifest、catalog、依赖锁、registry、RelayShelf、同步/推送或消息界面。

遵循父卡、PLAN01、T7.1/T9、PRD4.4 与 C-05：只配置 Hub，复用现有主题。Compose → ViewModel → Repository，状态由只读 `StateFlow<AuthState>` 发布。状态区分未认证、登录中、恢复校验、已认证、失效、可重试错误，以及安全存储/TLS/无效响应错误；`session` 仅在已认证状态出现。账号/设备元数据可展示，Bearer 不进入 UI/状态对象。

- `AuthRepository(context)` 组合真实 `HubClient`、`SessionStore`、`InstallationIdentity`。`initialize()` 启动读取规范地址，执行 `SessionStore.restore(attempt)` 后调用真实 `HubClient.session`，成功并核对保存的 session.id、安装 device_id 与票据后才认证。这里的“真实调用”指生产接线，测试不冒充真实部署验证。
- 非凭据地址在 Repository 同文件内的 `HubAddressFile` 保存到 `noBackupFilesDir/hub-address.v1`，内容仅规范化 HTTPS 地址。复用 S02 已存在的 `atomicWrite`（同目录临时文件、文件 fsync、原子替换），不改其实现；坏地址/超限文件删除后重新配置。地址不作为部署实例 ID；不声称目录 fsync、跨文件事务或断电保证。
- 启动自动恢复，返回前台时已认证状态再次 GET 验证；也提供“验证会话”和恢复失败后的“重试恢复”。401 使本地会话失效并说明重新登录原因。网络/429/5xx 仅显示可重试状态，保存的恢复凭据保留给显式 GET 重试；登录失败不会缓存密码或自动重发登录。
- 安装 UUID 来自 S02，服务返回的每次 session.id 单独用于会话身份。恢复响应出现另一 session.id/device_id 时清理并要求重新认证，不将另一身份当作恢复成功。
- 密码只使用 Compose `remember` 的短暂输入值与单次请求参数；不经 `rememberSaveable`、`SavedStateHandle`、磁盘、日志。提交、状态切换、离开前台和退出组合时清空输入引用。JVM 字符串不可原地擦除，不声称物理内存擦除保证。
- 切址通过显式“更换地址 / 取消”操作，先同步提升 Repository 代次并撤下内存身份，再在 IO 线程清 SessionStore 和地址配置。新地址连接也先清旧凭据。注销先撤下身份并清本地，尝试服务端 logout；离线/429/5xx 明确远端注销未确认，401 可确认会话已不可用。删除失败不显示持久清理成功，仍尽力尝试远端注销；失败后不能用“重试恢复”重新认证该旧会话。
- 磁盘操作用 IO 调度器和 Mutex 串行；连 `noBackupFilesDir`/安全存储对象构造也延迟到 IO 操作。Repository 自身代次隔离 UI/内存结果，SessionStore 票据隔离持久化结果。发布、save 和 clear 都检查所属代次，旧 401 不清新会话，迟到登录/注销不覆盖后来身份。身份终止通过 `state` 中撤下 `session` 表达，供后续同步接线；本卡没有 outbox/发送实现。
- ViewModel 保留跨配置变化的状态，命令取消上一操作并以 `UNDISPATCHED` 启动，使身份隔离不延迟到下一帧。本地终止清理使用 `NonCancellable`，迟到结果仍受代次约束。
