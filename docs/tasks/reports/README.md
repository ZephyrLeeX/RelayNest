# 执行证据目录

当前只有格式说明，没有已执行/已通过记录。

- 开发/研究：`<任务ID>-implementation.md`，说明结果、真实验证、基线/实现SHA、局限和下一任务所需接口摘要。
- 审计：`<任务ID>-audit-01.md`，必须固定精确SHA，结论 PASS / CHANGES_REQUIRED / BLOCKED；代码只读，报告可以提交。
- 修复：`<任务ID>-fix-01.md`，逐条对应审计发现；单独提交并重审。
- 集成：`<任务ID>-integration-01.md`，记录集成前/后SHA、相关检查和证据；报告本身后续提交，不把它自己的SHA写成同一提交内可预知值。
- 门槛：使用来源任务报告，避免另建重复大报告；摘要≤800中文字符，大日志放受控测试产物并给定位，禁止凭据/正文/外部源码全量归档。

实施报告随代码提交时无法在同一文件自引用最终SHA：报告写父基线和“SHA见任务交接/台账”，提交后将实际SHA交给调度更新台账。不得写占位SHA冒充真实提交。审计和集成针对代码的精确SHA/组合，不把只改报告的提交误当实现变更。

完整模板与角色权限见 [WORKER_PROTOCOL.md](../WORKER_PROTOCOL.md)。
