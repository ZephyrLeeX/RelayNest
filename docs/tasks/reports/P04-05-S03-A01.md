## 编号发现

### P04-05-S03-A01-F01：撤销接口 401 稳定机器码不符合冻结契约（P2）

- 条件：对 `DELETE /api/v1/devices/{id}/session` 使用缺失、无效、过期、已撤销的管理员凭据或 Bot 凭据。
- 契约：`server/api/openapi.yaml:524` 的 `x-error-codes` 明确列出 401 `AUTHENTICATION_REQUIRED`；`server/api/README.md:197` 也说明此机器码。Error.code 是供客户端稳定分支的字段。
- 实际：`server/internal/devices/http.go:110` 进入真实公共 `RequestSecurity.Authorize`；`server/internal/auth/request_security.go:81` 和 `:113` 对凭据/会话失败写 `AUTHENTICATION_FAILED`。`devices.TestDeviceHTTPRejectedRequestsDoNotMutate/bearer-random` 经真实 mux/SQLite DELETE，并明确断言该实际码，本次独立四包非缓存与 race 均通过。这证明现有测试与实现一致，但没有证明冻结操作契约一致。
- 独立实际请求反例：在 `/tmp` 复制原测试文件并仅附加 `TestAuditFrozenRevokeAuthenticationCode`，用 `go test -overlay <临时映射> -count=1 ./internal/devices -run '^TestAuditFrozenRevokeAuthenticationCode$' -v`，复用原真实 mux/文件SQLite fixture，分别以空凭据和错误Bearer请求有效目标DELETE，强断言冻结码 REQUIRED。两次均输出 `status=401 cache=no-store actual=AUTHENTICATION_FAILED want=AUTHENTICATION_REQUIRED`，测试退出1（0.143s），为预期缺陷反证；临时映射与文件已移除，未修改源码或弱化原断言。
- 当前明确受影响操作为冻结声明 REQUIRED 的 DELETE 设备会话路由：入口凭据拒绝、Inspect失败和仓储提交前 actor失效后经 WriteSessionError 输出的401均如此。GET也复用该公共入口并沿API README说明，但本finding以DELETE明确的operation扩展为锚点；不将整个auth/Bot现有错误语义一概判错。
- 影响：按已发布操作错误码处理的客户端无法命中契约规定的认证恢复分支。HTTP 401、拒绝无续期、无撤销副作用本身正确；未发现授权绕过。
- 归因与修复方向：这是前置 S01 既有公共响应与设备操作契约的差异，S01 实施报告也明确记录其输出 FAILED。调度已确认没有批准统一401码偏差的记录。S03 必须复用该公共入口且禁止改 auth/API，不能在消费者复制认证或悄悄改契约。由调度安排限定修复规划：评估设备路由响应适配是否完整覆盖入口与提交前失败，或最小公共入口扩展如何保持既有消费者行为；以证据选择实现，禁止直接全局替换或改API豁免，再以固定新SHA重审。不能仅以此前S01已审计或更改测试预期关闭。
- 复验：从真实 production 装配分别请求缺凭据、错误 Bearer、过期/撤销会话及两类 Bot 凭据 DELETE，核对最终批准契约的精确 Error.code、401/no-store、无 Cookie、全会话状态不变与无通知；重跑受影响 auth/devices/httpapi/cmd 四包。若统一公共安全码，覆盖既有 auth/Bot 消费者兼容性。
