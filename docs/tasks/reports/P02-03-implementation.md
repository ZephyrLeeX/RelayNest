## 实测结果矩阵

| 场景 | 关键结果 |
| --- | --- |
| **正常杀进程（am kill，等效最近任务划掉）+ HIGH，未开自启动** | 干净条件（亮屏/解锁/无 Doze/待机桶 ACTIVE）下 **20s+ 进程不拉起、消息不投递** |
| 同上，**已开自启动** | **5 秒内进程拉起（新 pid）+ 消息送达** |
| **Token 轮换（卸载重装）** | 新 token `ch0L0-0C…fX4o`；**旧 token 发送返回 HTTP 404 `NotRegistered` / `errorCode=UNREGISTERED`**；新 token 收发正常（543ms） |
| **重启（不碰应用）** | ① WorkManager periodic 于开机约 3.5 分钟后拉起进程并运行补偿（无任何推送参与）；② 无代理时 GMS 通道死（mtalk/firebaseinstallations 100% 丢包），HIGH 消息滞留服务端；③ 代理开启后约 10 秒通道重建、消息送达（累计挂起 167s）；④ token 跨重启不变（`eNXTP-4t…RgdY`） |
| **force-stop（P02-02 已测）** | 进程停止态中推送完全不可达，重开后 110ms 补偿同步——与正常杀进程行为本质不同，分开记录成立 |

积压冲刷模式三次复现：401（181s）、601（210s）、701（~155s）均为「后续实时消息/通道事件激活后补达」，无一例随前台打开自动冲刷。

## 对产品设计的直接输入

1. **ColorOS 自启动管控是目标设备最大可靠性风险**（超过 Doze）：进程死后（划掉/被杀），未开自启动的应用无法被推送拉起；产品必须引导用户开启自启动，并将「打开应用即补偿同步」作为兜底主路径（与 P02-02 结论互相印证）。
2. **旧 token 错误码实测为 HTTP 404 `UNREGISTERED`**：P09-03 服务端适配可据此实现 T9.1 的「明确 UNREGISTERED 才移除设备记录」；网络类错误不移除的规则维持。
3. 重启后无需用户打开应用：WorkManager 持久化调度自行拉起进程跑补偿；FCM 通道重建依赖 Google 可达网络（本环境=代理开启）。
4. Token 生命周期：卸载重装必换 token；重启/进程死亡不换。

## 额外发现（环境操作性）

- ColorOS 拦截 adb 静默安装（要求深度扫描），`adb install` 挂死、需手动安装——真机自动化测试链路需规避（模拟器 CI 不受影响）。
- 无线 adb 重启后不自动广播 mDNS，需在手机上打开一次「无线调试」界面。
- 锁屏页（已亮屏未解锁）不投递积压消息，需真正可见前台或通道事件。
