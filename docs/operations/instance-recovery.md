# 停服恢复、克隆与更换实例身份

普通重启、原库无回滚的停机迁移保留实例 ID，不执行本维护命令。清库新建产生新 ID。备份恢复、历史回滚和复制为第二个独立部署，必须先完成下列人工流程，成功后才能恢复入口并重新登录。

1. 停止全部 RelayNest 服务进程、后台管理命令和自动重启机制；隔离外部入口。确认旧部署不再接收流量。`--confirm-offline` 是维护者对这些前置条件的确认。
2. 在停机状态备份数据库及其 SQLite 配套文件，并按既有备份方案备份关联文件。维护命令不生成备份、不自动发现副本。
3. 核对要处理的数据库和原实例 ID；从恢复记录安全取得 UUID，不在共享日志中记录敏感路径。对已存在、迁移完整的目标数据库运行：

   ```text
   relaynest instance rotate-id --db PATH --expected-instance-id UUID --confirm-offline
   ```

4. 仅退出码 0 表示换 ID、管理员认证代次推进及全部 Web/Android 会话撤销已提交。失败保持入口关闭，排查后重试；不能以保留旧 ID 的恢复方式绕过维护。
5. 重启服务后，通过公开实例探测读取新的 ID，再恢复入口。全部管理员客户端需要重新登录。Bot 凭据和 `sync_epoch` 保留，不自动转移客户端草稿或待发消息。

参数全部必填；拒绝重复、未知、位置参数、畸形 UUID 和指定新 ID。命令仅显示固定结果文本，不输出新旧 ID、凭据、数据库路径或 SQL。退出码：0 成功，2 用法或确认错误，3 数据库忙或独占锁不可用，4 身份缺失/腐败/不匹配或迁移未完成，1 其他存储、随机、撤销或提交错误。

独占锁与 SQLite 写锁用于拒绝冲突，不能证明任意旧版本、其他机器或数据库副本上的服务已经停止。没有写事务的旧服务也可能仍在运行；人工停服、隔离入口和控制旧副本是必要条件。维护不支持运行中替换数据库或在线换 ID。

## 当前推送实现与后续门禁

本实现基线 `fad32a1` 的 0001–0005 迁移仅含 `system_state`、`changes`、`administrator`、`sessions`、`bots`、`bot_credentials`、`instance_identity`（及迁移台账）；不存在生产推送设备映射表或注册/投递仓储。本命令不凭空创建推送表。

未来引入推送映射时，注册、待办和发送前复核必须绑定实例 ID 与管理员认证代次；换 ID 必须在同一维护事务中撤销所有实际映射，失败全部回滚。推送实现必须补充恢复/克隆后的旧注册和待办失效测试，才能通过其验收；不能将本次“当前无映射”当作未来免撤销依据。

本版 HTTP 主进程从打开/迁移数据库之前到请求排空、Store 关闭之后持同 inode 共享 flock；维护命令持排他 flock 到事务结束与 Store 关闭。路径别名不能绕过该本地锁，但既有 admin 工具、旧版本和他机进程不因此纳入自动检测。

集成含 `0006_messages.sql` 的版本时，真实 `push_jobs(session_id, device_id)` 通过外键 `ON DELETE CASCADE` 随会话删除；必须在该真实迁移组合中重跑维护、提交失败回滚及恢复/克隆测试，确认 pending 清空，不能仅凭 0001–0005 测试宣称通过。它是待办表，仍不代表已经存在推送设备注册映射。
