# RelayNest — 工程开发规范

## 1. 编码规范

- 遵循各语言官方规范及仓库已有配置。
- Go：使用 `gofmt`，错误显式处理，合理传递 `context.Context`。
- Kotlin：遵循 Kotlin 官方编码风格，UI 使用 Jetpack Compose，避免阻塞主线程。
- Web：遵循项目选定的 TypeScript、Lint 和格式化配置。
- **代码注释统一使用中文**，代码标识符及必要的技术术语保留英文。
- **重要代码必须添加注释**，尤其是核心业务逻辑、复杂算法、并发处理、状态转换、安全校验及容易误解的实现。
- 注释重点解释设计意图、约束和实现原因，避免逐行描述显而易见的代码。
- 优先复用现有模块，保持代码简单、职责清晰，避免重复实现和过度抽象。
- 公共接口或关键行为变更应同步更新相关技术文档。
- 不引入未经确认的框架、大型依赖或额外基础设施。

## 2. 测试与质量

- 修改代码后执行受影响模块的格式检查、静态检查和测试。
- 修复 Bug 时，尽可能增加能复现问题的回归测试。
- 不得通过删除测试、跳过检查或弱化断言来掩盖失败。
- 无法运行的测试应说明原因，不得声称已经通过。
- 优先执行相关模块测试；重大改动再执行更大范围的验证。

## 3. Git 工作流

- **每个独立任务完成后必须单独创建一个本地 Git 提交。**
- 不同任务不得合并提交；一个任务涉及多个文件时，可以包含在同一个提交中。
- 遵循 Conventional Commits 格式：`type(scope): description`。
- 常用类型：`feat`、`fix`、`refactor`、`test`、`docs`、`chore`。
- scope 使用模块名，例如 `android`、`server`、`web`、`moviepilot`。
- 提交前必须检查 `git diff` 和 `git status`，确认只包含当前任务的修改。
- 提交前执行相关测试；测试未通过时应先修复，无法验证时必须说明，不得隐瞒。
- 不得擅自覆盖或提交其他任务及用户已有的未提交修改。
- 不自动推送远端仓库，除非我明确要求。
- 不擅自使用 `push --force`、`reset --hard`、改写历史等破坏性操作。
- 不提交密钥、凭据、构建产物及临时文件。

## 4. 任务完成要求

每个独立任务完成后，简要报告：

1. 本次完成的修改。
2. 执行的测试及结果。
3. 本地 Git 提交 SHA 和提交信息。
4. 尚未解决的问题或风险。
